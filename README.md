# AdrobotTask

Интерфейс для создания тестовых кампаний, редактирования офферов и просмотра статистики. Бэкенд на FastAPI и SQLAlchemy, миграции через Alembic, фронтенд на React и TypeScript.

## Режимы

| Режим | Данные | Что можно делать |
| --- | --- | --- |
| `demo` | Локальная SQLite, вымышленные справочники и статистика | Создавать кампании, менять офферы, смотреть отчёт |
| `keitaro` | Keitaro Admin API | Создавать выключенные кампании, менять офферы тестовых кампаний и смотреть отчёты |
| `readonly` | Keitaro Admin API | Читать кампании, потоки, справочники и отчёты |

В деморежиме GEO-поток показан как симуляция. Настройки, созданные в этом режиме, хранятся в SQLite.

## Запуск демо

Нужны Python 3.12+ и Node.js 22.12+ (либо Node.js 24 LTS). Команды ниже для macOS или Linux, из корня репозитория.

```bash
cp .env.example .env
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt

cd frontend
npm ci
npm run build
cd ../backend

alembic upgrade head
python -m app.seed
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [приложение](http://127.0.0.1:8000/) или [Swagger](http://127.0.0.1:8000/docs). Фронтенд после сборки отдаёт FastAPI. Демо-кампания называется `test_kalinin_demo`. Команду заполнения можно запустить повторно, она не создаст дубликат.

Для разработки фронтенда вместо сборки можно запустить `npm run dev` из `frontend/`. Vite проксирует запросы `/api` на FastAPI.

## Миграции

Запускайте команды из `backend/` в активированном виртуальном окружении. Файл SQLite по умолчанию создаётся в `backend/adrobot.sqlite3`. Конфиг читается из `.env` в корне проекта.

```bash
alembic current
alembic upgrade head
alembic check
```

После изменения моделей создайте миграцию командой `alembic revision --autogenerate -m "описание"`, проверьте получившийся файл и примените его. `alembic downgrade base` удаляет таблицы вместе с данными. Используйте его для проверки обратимости только на отдельной тестовой базе.

## Подключение Keitaro

В `.env` укажите следующие настройки и перезапустите FastAPI.

```dotenv
ADROBOT_MODE=keitaro
ADROBOT_KEITARO_URL=https://tracker.example
ADROBOT_KEITARO_API_KEY=
ADROBOT_TIMEZONE=Europe/Moscow
```

В `ADROBOT_KEITARO_API_KEY` подставьте свой ключ. Приложение добавляет путь `/admin_api/v1` и передаёт ключ в заголовке `Api-Key` на сервере. Ключ не нужен для демо, не передаётся в React и не должен попасть в Git. Для сверки отчётов укажите тот же часовой пояс, что и в трекере.

Выберите группу и оффер из справочников Keitaro. Если домен или источник доступен, выберите его в форме. Без них можно сохранить выключенную кампанию с двумя потоками и назначить настройки позже в Keitaro. Для проверки полного сценария по ТЗ нужны оба справочника. Если ключ видит пустые списки и получает HTTP 403 при добавлении записей, попросите администратора стенда выделить тестовый домен и источник и открыть к ним доступ. Для подключения только на чтение укажите `ADROBOT_MODE=readonly`.

Кампания создаётся с префиксом `test_kalinin_` и остаётся выключенной. Первый поток проверяет код страны и перенаправляет на Google. Второй используется, когда ни один обычный поток не подошёл. Если настройка одного из потоков завершилась ошибкой, приложение отправляет созданную кампанию в архив. Если Keitaro не подтвердил архивирование, интерфейс покажет ID кампании для проверки.

Редактор разрешает запись в офферные потоки кампаний с префиксом `test_kalinin_`. При обновлении он передаёт полный список офферов со статусами и долями. Новый оффер получает среднюю долю, оставшиеся доли масштабируются пропорционально. Сумма долей активных офферов после изменения составляет 100%. Запускайте приложение одним процессом Uvicorn. Параллельные записи через это приложение выполняются последовательно. Во время редактирования через приложение избегайте одновременного изменения того же потока напрямую в Keitaro.

Сервис рассчитан на локальный запуск. Доступ к API извне требует отдельной аутентификации. Запрос `POST /report/build` строит отчёт, а не меняет настройки кампании. Контракт описан в [документации Keitaro Admin API](https://admin-api.docs.keitaro.io/).

## Как устроено

- `backend/app/demo.py` хранит правила создания демо-кампаний и изменения офферов. Второй поток назначен для офферов. Добавление уже привязанного оффера ничего не меняет. Последний оффер удалить нельзя.
- `backend/app/keitaro.py` работает с кампаниями, потоками, справочниками и отчётами через Admin API. При ошибке показывает статус запроса без тела ответа и ключа.
- `backend/app/models.py` описывает кампании, связи с офферами и дневную статистику. Изменение кампании выполняется в транзакции.
- `frontend/src` содержит форму создания, список кампаний и редактор с периодом отчёта. При нескольких подходящих потоках пользователь выбирает нужный по имени и ID.

Отчёт группирует данные по офферам за выбранные даты. При чтении Keitaro используются фильтры кампании и потока. CR считается как `конверсии / клики × 100`. В общей строке сначала суммируются клики и конверсии. При нуле кликов CR отображается как прочерк. Статистика снятого оффера остаётся в истории за период, где у него были данные.

## Проверки

```bash
# Из корня репозитория в активированном окружении
python -m pip install -r backend/requirements-dev.txt
cd backend
python -m pytest -q
```

Тесты проверяют создание кампании и валидацию справочников, редактор офферов, даты и CR, запрет записи в readonly, запросы к Keitaro и архивирование частично настроенной кампании. Внешние запросы в тестах подменены.


## Что показать в скринкасте

1. Создайте кампанию в демо. Введите название и код страны, выберите оффер и покажите оба потока.
2. Откройте офферный поток. Добавьте второй оффер, снимите один из них и покажите, что последний остаётся в кампании.
3. Откройте `test_kalinin_demo`. Измените даты отчёта. Покажите, что итоговый CR рассчитан от суммы конверсий и кликов.
